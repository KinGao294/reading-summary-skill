# 追问协议：基于书库原文回答

书已入库后的每一轮对话都走这份协议。这是这个技能的主要价值——
一次下载，长期可查，而且每个答案都能被用户自己复核。

**核心规则：先检索，再读原文，最后作答，答案必须带定位。**

---

## 接手一本书

新会话或长时间之后，先花三步恢复上下文，不要重读全文：

```bash
python3 scripts/booklib.py list                    # 库里有什么
python3 scripts/booklib.py show <slug> --sections 30   # 元数据 + 章节骨架
cat library/<slug>/notes.md                        # 上一轮读出来的带定位笔记
```

`notes.md` 是上次精读的成果，通常直接就能回答一半问题；覆盖不到的再回 `text.txt`。

---

## 标准动作

### 1. 把问题拆成检索词

用户问的词不一定是原文用的词。至少准备 2–3 个变体：

| 用户问 | 应该检索 |
|---|---|
| 黛玉葬花在第几回 | `葬花`、`花冢`、`埋香` |
| 贾府是怎么败的 | `查抄`、`錦衣軍`、`世職`、`revoke` |
| 宝钗这个人怎么样 | `寶釵`（先定位高频章），再逐章读 |
| 作者怎么定义 attention | `attention is`、`we define`、`Definition` |

**繁简是硬坑。** 古登堡与维基文库的中文正文多为繁体，用简体检索会一无所获。
先看 `META.json` 的 `language` 与 `show` 输出里的字形，再决定用哪种字体检索；
拿不准就两种都试。

```bash
python3 scripts/booklib.py grep hong-lou-meng "葬花" --max 20
```

`grep` 支持正则，多个候选词可以一次打完：

```bash
python3 scripts/booklib.py grep hong-lou-meng "葬花|花冢|埋香" --max 30
```

### 2. 读命中处的原文

`grep` 只给一行上下文，**不能只凭这一行作答**。拿到章节号后去读：

```bash
python3 scripts/booklib.py read hong-lou-meng --chapter 27
python3 scripts/booklib.py read hong-lou-meng --start 6380 --limit 120   # 精确行窗口
```

章太长读不动就用行窗口，围着命中行前后各读一两百行。

### 3. 作答

格式要求：

- **结论先行**，再给依据；
- **每个事实性断言带定位**（`第二十七回` 或 `L6393`）；
- 涉及原文措辞时短引一两句，不要整段搬；
- 跨章的问题按时间顺序给出定位链，让用户能顺着读下去。

**示例**

> 黛玉葬花在**第二十七回「滴翠亭楊妃戲彩蝶　埋香冢飛燕泣殘紅」**。
>
> 起因在前一回：黛玉夜访怡红院吃了闭门羹（第二十六回），第二天正逢饯花之期，
> 她把落花收葬并作《葬花吟》。文本里"儂今葬花人笑痴，他年葬儂知是誰"（L6406）
> 是全诗的题眼——她葬的是花，说的是自己。
>
> 这条线后面还有两处回响：宝玉在山坡后听到这句而恸倒（第二十八回，L6416）；
> 第三十回宝玉见龄官画蔷，心里拿她与"颦儿葬花"作比（L7277）。
> 所以葬花不是一个孤立场面，是黛玉结局的预告。

三个定位都可以用 `read` 复查——**这就是"扎根原文"的可操作定义**。

## 常见追问类型

| 类型 | 做法 |
|---|---|
| **情节定位**（"X 在第几回"） | `grep` 关键词 → 读命中章确认 → 给回目全名 |
| **人物分析**（"宝钗是个怎样的人"） | `grep` 人名统计高频章 → 精读 3–5 个关键场景 → 归纳，每条带定位 |
| **主题追踪**（"贾府的钱是怎么没的"） | 多关键词 `grep` → 按章号排序 → 给出时间线 |
| **对比**（"黛玉和宝钗有什么不同"） | 各自取 2–3 个平行场景，逐项对照，不要空谈性格标签 |
| **原文核对**（"是不是有这么一句"） | `grep` 原句片段；查不到就说查不到 |
| **超出本书**（"作者其他作品呢"） | 明确说明这超出已入库范围，可提议再入库一本 |

## 找不到的时候

检索不到就直说，不要用常识补。标准口径：

> 我在库里这一版《红楼梦》（Project Gutenberg #24264，程高本 120 回）里没有检索到
> 「<关键词>」。可能是三种情况：这个说法在原文用词不同、属于版本差异、
> 或者本来就不在这个版本里。你要是记得大致情节，我换个词再找一遍。

三条注意：

- **"检索不到"不等于"不存在"。** 说明是这一版检索不到，并主动提出换词再试。
- **不要用记忆填空。** 凭印象补出来的情节和引文，正是这个技能要消灭的东西。
- **版本差异要说。** 程高本 vs 脂评本、节译本 vs 全本，都会造成真实差异。
  `META.json` 里有版本信息，直接引用。

`chapters.json` 的 `mode` 是 `windows` 时（来源没有可识别的章节结构），
改用行号定位并说明这一点，不要编造章节号。

## 维护书库

追问过程中挖出的新发现，**写回 `notes.md`**，下次就不用重查：

```markdown
## 第二十七回 葬花
- 《葬花吟》题眼 "儂今葬花人笑痴，他年葬儂知是誰"（L6406）
- 回响：第二十八回宝玉听恸（L6416）；第三十回龄官画蔷对照（L7277）
```

不要因为追问就去改 `SUMMARY.md`——那是一次精读的成果，除非用户要求重写，否则保持稳定。
`notes.md` 才是持续增长的那一份。

`text.txt` 与 `source/` 永远只读。要换版本就用新 slug 另存一份，不要覆盖。
